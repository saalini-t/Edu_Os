# EduOS evaluation assets

Everything here is **synthetic**: the corpus is original text written for EduOS and contains no student data.

| Path | Contents |
|---|---|
| `data/corpus/computer_networks_supplement.pdf` | Synthetic supplementary Computer Networks notes (7 pages). Generated by `backend/scripts/make_seed_pdf.py` from `backend/scripts/supplement_pages.py`. Evaluation only; not part of the demo seed. |
| `../backend/seed/computer_networks.pdf` | The demo seed PDF (6 pages), also used as part of the evaluation corpus. |
| `data/retrieval.jsonl` | 54 labelled questions: 32 `answerable`, 6 `ambiguous`, 8 `out_of_corpus`, 8 `in_domain_missing`; split 27 `dev` / 27 `test`, stratified by category. |
| `THRESHOLDS.md` | Pre-registered threshold-selection procedure, selected values and run log. |
| `reports/` | Machine-readable (`report.json`) and human-readable (`report.md`) output of each evaluation run. |

## Label format

```json
{"id":"q05","split":"dev","category":"answerable","question":"...",
 "gold":[{"phrase":"three duplicate acknowledgments trigger fast retransmit","grade":2},
         {"phrase":"Fast recovery then sets ssthresh","grade":1}]}
```

* **Labels are evidence phrases, not chunk IDs**, because chunk IDs are regenerated on every ingestion. At run time every chunk whose
  normalised text contains a gold phrase is relevant, with the maximum grade of the phrases it contains (grade 2 = primary evidence,
  1 = supporting). The loader fails if a phrase matches no chunk.
* `category`: `answerable` (corpus contains the answer), `ambiguous` (too vague; expected behaviour is a clarification question),
  `out_of_corpus` (not about networking), `in_domain_missing` (about networking, but the corpus does not contain the answer).
* **Reproducibility:** ranking ties are broken by title/page/chunk index (never by random IDs), so repeated runs give identical metrics (verified). Reports produced before 2026-10-09 evening carried tie-breaking noise and are marked superseded in `THRESHOLDS.md`.
* Authorship: all labels were written by one engineer in a single pass and have **not** been independently double-annotated, so
  inter-annotator agreement is unknown. Treat results as development evidence, not a benchmark.

## Limitations

* 13 + ~20 chunks is a tiny corpus; ranking differences between methods are measured on few candidates and many metrics saturate.
* The corpus was written by the same author as the questions, so lexical overlap between questions and evidence is probably higher than for real student questions.
* `in_domain_missing` questions are hand-picked hard negatives; real distributions will differ.

## Running

```bash
cd backend
EVAL_DATABASE_URL=postgresql+psycopg2://USER:PASS@HOST:PORT/eduos_eval_test python -m app.evaluation.retrieval_eval --mode fts --splits dev test --workflow
```
The database must be disposable (its name must contain `test` or `eval`); the run drops and rebuilds the `core`, `orch` and `know` schemas.
